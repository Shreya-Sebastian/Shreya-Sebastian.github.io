Software Architecture · TU Delft

Fault-tolerant sensor ingestion

A proof of concept for a smart home system: sensor data keeps flowing through network outages and is resynchronised when the connection returns.

Overview

This proof of concept demonstrates a fault-tolerant data ingestion architecture for IoT sensors in a smart home. Simulated sensors buffer their data locally during network outages and resynchronise in chunks when they reconnect.

Architecture

  • Ingestion server. A FastAPI service that receives sensor readings, validates them with Pydantic and publishes them to a RabbitMQ queue.
  • Consumer. A separate process that consumes and processes messages from the queue.
  • Sensor simulator. Simulates many sensors. A disconnected sensor stores its readings locally (store-and-forward) and uploads its backlog on reconnection.
  • Orchestration. Docker Compose runs the server, consumer and broker together.

Testing

A three-phase simulation checks the behaviour end to end: normal operation, a disruption in which one sensor goes offline while the others keep sending, and resynchronisation, where the backlog is processed alongside live data.

A GitLab CI pipeline runs style checks with black, builds a Docker image and pushes it to the GitLab container registry, then runs pytest suites for error handling, scalability under high-concurrency load and end-to-end behaviour inside that image against a RabbitMQ service.
